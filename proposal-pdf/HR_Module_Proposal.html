Section 01

01  Executive Summary

This document describes a complete HR system for a factory-size workforce. It handles the daily work of the HR team from the first day an employee is hired to the last day of their service, and every payroll, leave, overtime and compliance report in between.

The scope is arranged in the same order you would follow in real life. First we set up the master data. Then we register employees, assign their designation and grade, put them on a shift with a rest day, and start marking their attendance. Leaves and overtime are approved as they come in. Payroll and wages run at month-end. Budgets are watched throughout. Compliance reports are produced at month-close. Dashboards show leadership what is happening.

Many HR products handle the easy work — employee records and leave — and stop when the real work begins. This system also handles wages-days calculation, arrears, locked attendance for audits, EOBI and Social Security filings, gratuity, overtime budgets, shift rotations, Alternate Saturday Off rules, and piece-rate coupons. Everything an HR team needs, in one place.

What you get on day one

  • One system for the whole HR job — no side-files in Excel.
  • A proper workflow for designation, grade, promotion and transfer.
  • A full shift and rest-day engine, including night rotations, ASO and off-day rules.
  • Payroll for salaried staff, wages workers and compliance-paid workers, using a tested days-calculation engine.
  • Overtime from request to posting, with a monthly budget per department and late-sitting for staff.
  • Budget dashboards for headcount, salary and overtime, with live variance by section.
  • An approval matrix you configure yourself, so every action goes to the right person.
  • Excel loaders for legacy data, so migration takes days, not months.
  • Ready-made compliance reports — EOBI, Social Security, Provident Fund, gratuity and ASO.
  • Emailed pay-slips, bank-transfer files, and printable monthly registers.
Section 02

02  Why This System Is Needed

In a factory, HR runs on a tight daily clock. Shift rosters are set on Friday for Monday morning. Wages are worked out on Sunday night so the bank can pay on Monday. An auditor can walk in on any day and ask to see a signed register. The system is built for that pace.

The problem this solves

  • Attendance sits in one tool, payroll in another, compliance in Excel — the same data keyed again and again.
  • Numbers on one report do not agree with numbers on another.
  • Corrections happen every day, but no one can prove who did what, when, or why.
  • Statutory filings are assembled by hand every month.
  • No one knows current headcount versus budget until the month ends.
  • Shift and rest-day rules live in a supervisor's head, not in the system.

What good looks like

  • One employee record used by every form.
  • Attendance flows from the biometric to payroll without anyone re-typing it.
  • Every approval is logged with the user, time and a note.
  • EOBI, Social Security and Provident Fund packs ready in one click.
  • A dashboard that shows how many people worked yesterday before you finish your morning tea.
  • No department can quietly go over its overtime or salary budget.

Section 07

07  What Runs Where

The system runs on standard Windows Server and SQL Server infrastructure, with lightweight desktop clients kept current by an auto-updater.

Server

Server

Windows Server 2016+; SQL Server 2016+ (Standard or Enterprise). Two catalogues — Live and Test — identical schema. File share for auto-update and payslip archive. Nightly full backup + hourly log backup; weekly off-site copy.

Client

Client

Windows 10 / 11; .NET Framework 4.5+. Auto-updater compares network build vs local build on launch. UI redistributables shipped alongside; no admin install per user.

Network

Network

Client → SQL over TCP 1433 (LAN or VPN). SMTP relay for pay-slip email; scheduler on server for daily jobs. Biometric ingest via shared folder or scheduled DB pull.

Optional

Web dashboards

ASP.NET MVC on IIS. Same SQL back-end — no data duplication. Chart.js dashboards vendored offline; no external CDN calls.
